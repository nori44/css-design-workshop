# CSSコーディング規約（たたき台B案：ゆるめ運用寄り）

> 生成条件：受託制作／4名チーム／中規模サイト／長期運用あり／厳しさ「ゆるめ」

## 1. 命名規則

- ゆるやかなBEMを推奨する。`Block__Element` を基本に、迷ったら短い名前でよい
  - なぜ：命名の議論に時間を使うより、あとから直せる状態を保つ方が生産的なため
- Modifierと状態クラスの書き分けは自由（`--modifier` でも `is-` でも可）。ただし同一ファイル内では統一する

## 2. ファイル構成

- Cascade Layers は `reset, base, components, utilities` の4層を基本とし、必要になったら追加してよい
- ファイル分割は「探しやすさ」を優先する。1ファイル500行までは分割しなくてよい
  - なぜ：ファイル数が増えすぎると、かえってどこに書くか迷うため

## 3. デザイントークン

- **2回以上使う値はトークン化する**（1回目は直書きでよい）
  - なぜ：使うか分からない値まで先回りでトークン化すると、トークン一覧が育ちすぎるため
- トークン名はFigmaと多少ずれてもよい。ただし対応表をREADMEに残す

## 4. 非推奨パターン

- `!important` は utilities レイヤーでのみ許可する
- 「禁止」より「推奨」で書く。例外は理由をコードコメントに残せば許容する
  - なぜ：例外を認めないルールは、守られなくなった時点で形骸化するため

## 5. ツールによる強制

- Prettier のみ必須とする（フォーマットの議論を消すため）
- Stylelint は導入したい人が設定案を持って提案してから
