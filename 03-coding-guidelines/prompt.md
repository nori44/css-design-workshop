# 持ち帰り用プロンプト

`my-guidelines.md` を書いたら、このプロンプトでAIにレビューしてもらいましょう。
`{ }` を自分のチームの情報に、`{my-guidelines.md の内容}` を実際の中身に置き換えて、ChatGPT / Claude などに投げてください。

```text
あなたは経験豊富なフロントエンドのリードエンジニアです。
以下は、ワークショップで作成した私たちのチームのCSSコーディング規約のたたき台です。
レビューして、改善点を指摘してください。

## チームの状況
- 人数とスキル感: {例: エンジニア4名。CSSが得意な人2名、バックエンド寄りが2名}
- 案件の種類: {例: 受託のコーポレートサイト制作。納品後も保守が続く}
- 技術スタック: {例: 素のCSS（ビルドなし）。Cascade Layersは使える環境}

## 規約
{my-guidelines.md の内容をここに貼り付け}

## レビューしてほしい観点
1. 「未決事項」に残っている項目について、決め方の提案
2. 項目間で矛盾しているルールがないか
3. 「なぜ」が書かれていない・弱いルールの指摘
4. チームの状況（人数・案件の種類）に対して、厳しすぎる/緩すぎるルールがないか
```

## 使うときのコツ

- 1回で終わらせず、指摘をもらったら直して、また投げる。この往復が規約を育てる
- 「未決事項」が埋まってきたら、その都度チームに共有して合意を取る
- 決めた規約をAIに渡して「この規約に沿ってレビューして」と使うと、規約が実際に機能し始める

---

## （参考）今日のたたき台 draft-a.md / draft-b.md を生成したプロンプト

ゼロから新しいプロジェクトの規約を作りたくなったときに使えます。

```text
あなたは経験豊富なフロントエンドのリードエンジニアです。
以下のチームのためのCSSコーディング規約のたたき台を、Markdownで作成してください。

## チームの状況
- 人数とスキル感: {例: エンジニア4名。CSSが得意な人2名、バックエンド寄りが2名}
- 案件の種類: {例: 受託のコーポレートサイト制作。納品後も保守が続く}
- 技術スタック: {例: 素のCSS（ビルドなし）。Cascade Layersは使える環境}
- デザインツール: {例: Figma。バリアブルで色と余白が定義されている}

## 規約に含める項目
1. 命名規則
2. ファイル構成（Cascade Layersの構成順を含む）
3. デザイントークンの運用ルール
4. 禁止事項・非推奨パターン
5. ツールによる強制（Prettier / Stylelint など）

## 条件
- 厳しさは「{厳格 / ゆるめ}」でお願いします
- 各ルールには「なぜそうするのか」を1行添えてください
- 新しいメンバーがオンボーディング資料として読める分量にしてください
```

「厳格」と「ゆるめ」の両方で生成して読み比べると、論点が浮かび上がります（`draft-a.md` / `draft-b.md` がまさにこの手順で作られたもの）。
